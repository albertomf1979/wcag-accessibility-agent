# WCAG Accessibility Agent — Project Context

## What this project is
A portable Agent Skill (`skills/wcag-accessibility/`) plus a standalone CLI agent built on the Anthropic SDK. Both audit, analyze, evaluate and correct digital products for WCAG 2.1 accessibility. The CLI generates structured reports and handoff documents (PDF + DOCX) for design and development teams.

The skill is installable with `gh skill install`, as a Claude Code plugin (`.claude-plugin/`), or uploaded to Claude.ai as `wcag-accessibility.skill`. It does not need Python or an API key.

Everything is grounded in the official W3C WAI standard (https://www.w3.org/WAI/). The CLI asks the user for discipline level (UX / UI / Dev) and WCAG conformance target (A / AA / AAA) in interactive mode; the skill uses defaults (Dev · WCAG 2.1 AA · analysis, no file changes) and only asks when information is missing.

## Tech stack
- Python 3.11+
- Node.js 18+ (required for axe-cli / Chromium headless scan)
- anthropic SDK (tool use, streaming)
- axe-cli / axe-core (full DOM WCAG scan via headless Chromium)
- httpx (URL fetching for HTML context)
- BeautifulSoup4 (HTML parsing)
- PyMuPDF (PDF export)
- python-docx (DOCX export)
- rich (CLI formatting)
- python-dotenv (env management)
- Cloudflare Workers/Pages (optional deployment for team web interface)

## Agent behavior rules
1. **Protocol**: The interactive CLI asks discipline level + WCAG target before any analysis (or takes `--discipline`/`--level`). The skill applies defaults and asks only when information is missing.
2. **Source of truth**: All WCAG knowledge comes from `skills/wcag-accessibility/` (SKILL.md + references/), grounded in W3C WAI. WCAG 2.1 is the base scope; WCAG 2.2 criteria are listed separately and only evaluated on request.
3. **Tool use loop**: The agent uses tools to fetch URLs, read files, load references, and export. It reasons between tool calls.
4. **Five modes**: análisis / auditoría / evaluación / corrección / handoff. User can combine them.
5. **Output**: Always produces structured markdown → optionally exported to PDF or DOCX.
6. **Evidence**: Findings state whether they come from an executed tool, code inspection or need manual checks. Never claim conformance from axe-core results alone.

After editing anything under `skills/wcag-accessibility/`, run `make skill-package` and `make test`.

## Key commands
```bash
python agent.py                                        # Interactive mode
python agent.py --url https://example.com              # Analyze a URL
python agent.py --file path/to/file.html               # Analyze a local file
python agent.py --url https://example.com --export pdf # Analyze + export PDF
python agent.py --url https://example.com --export docx # Analyze + export DOCX handoff
python agent.py --file index.html --fix /path/to/project # Analyze + apply fixes
python agent.py --url https://example.com --fix /path/to/project # URL + apply fixes
node skills/wcag-accessibility/scripts/axe-scan.mjs https://example.com  # axe-core scan only
make test                                              # local validations (no API key)
make skill-package                                     # rebuild wcag-accessibility.skill
```

## Agent tools
- **axe_scan**: Run axe-core via headless Chrome (`skills/wcag-accessibility/scripts/axe-scan.mjs`) — rendered DOM scan, always called FIRST for URLs
- **fetch_url**: Fetch and parse HTML from a URL — used AFTER axe_scan for qualitative context
- **read_file**: Read local files (HTML, CSS, JS, JSX, TSX, Vue, Svelte, images, PDF)
- **list_directory**: Explore project structure to understand tech stack before correcting
- **write_file**: Write corrected files to disk (always creates .bak backup first)
- **export_report**: Export reports to PDF or DOCX

## Environment variables
- `ANTHROPIC_API_KEY` — required
- `WCAG_MODEL` — default: claude-sonnet-4-6 (override for faster/cheaper runs)
- `WCAG_OUTPUT_DIR` — default: ./outputs
- `CHROMEDRIVER_PATH` — optional, ChromeDriver matching the local Chrome when axe-cli's bundled driver does not

## Cloudflare integration
If deploying a web interface for teams, use Cloudflare Pages + Workers:
- Worker handles API calls to Anthropic (keeps key server-side)
- Pages serves the frontend
- D1 can store audit history
- Account credentials in .env as CF_API_TOKEN and CF_ACCOUNT_ID
